# Onboarding, auth and legal screens — state table

Routes live in `app/(public)/` (Stack, no native headers). The root layout keeps the group
mounted while onboarding is incomplete or the user is signed out; after `setSession` the guard
moves the user to the member tabs on its own. Test ids: `src/features/{onboarding,auth,legal}/testIds.ts`.

Every state exists in `ru`, `uz` and `en` (`auth.json`, `onboarding.json`, `legal.json`,
`errors.json`) and in both themes; the Maestro flows in `e2e/` cover the happy path and the
invalid-code path (not run locally — no emulator on the authoring machine).
